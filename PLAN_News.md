# AI News Radar — план части News

Новости об ИИ из многих независимых источников. Дубли склеиваются в один сюжет, шум отсеивается. Дайджест приходит по расписанию, срочное — сразу. Всё это идёт в бот DEEper и в раздел «Радар» приложения.

Главная проблема, которую решаем: одна новость приходит из 100 каналов. Нужно получать её один раз, с пометкой, откуда она и можно ли ей верить.

Это часть DEEper, а не отдельный проект: папка `my_browser/news/`, свой `CLAUDE.md`, своя группа зависимостей `news`. Где DEEper расходится с первой версией плана, написано в разделе «Решения».

---

## Как работать с этим планом

- Делаем этапы по порядку. Не переходим дальше, пока этап не прошёл свой «Готово, когда».
- В начале сессии: «Прочитай PLAN_News.md, делаем этап N». Сессию можно открыть прямо в папке: `cd my_browser/news && claude`.
- Каждый этап заканчивается проверкой из «Готово, когда» и коммитом. Как во всём DEEper, без pytest: одноразовые прогоны, тестовая модель `dev/mock_llm.py` и `/check-project` перед коммитом.
- Если решение отличается от плана, обнови этот файл (раздел «Решения»), а не держи в голове.
- Не добавлять функции из раздела «Потом» без явной просьбы.

## Стек

| Задача | Инструмент | Почему |
|---|---|---|
| Язык | Python 3.12 | как весь DEEper |
| Telegram | бот DEEper (aiogram 3, часть `bot`) | новости приходят в тот же чат, что и отчёты |
| Telegram-каналы | веб-превью `t.me/s/<канал>` | публичные каналы читаются без входа в аккаунт и без риска для него |
| RSS / Atom | feedparser + httpx | |
| Хранилище | SQLite: `news.sqlite` рядом с отчётами (volume на Railway) | один файл, хватает для одного пользователя |
| Эмбеддинги | fastembed, мультиязычная модель (например `paraphrase-multilingual-MiniLM-L12-v2`), в дочернем процессе | ONNX без PyTorch, RU+EN в одном пространстве; дочерний процесс не держит модель в памяти Railway |
| LLM | DeepSeek через `create_chat_completion` gpt-researcher; расход считает `common/costs.py` | как в остальном DEEper; тестовая модель подменяет его бесплатно |
| Расписание | цикл в потоке, раз в минуту | как цикл исследований; без APScheduler |
| Настройки | таблица `settings` с проверкой pydantic; начальные значения — в `config.py` | меняются из бота и приложения без перезапуска |
| Проверка | одноразовые прогоны, `/check-project`, eval склейки на этапе 4 | тестов в DEEper нет по решению владельца |
| Запуск | Railway, общий процесс `app.py` | сервер там уже работает круглосуточно |

## Архитектура

```
[RSS лабораторий, СМИ, аналитиков, сообществ]  [HF Daily Papers]  [Telegram t.me/s]
                         \                          |                 /
                          ▼                         ▼                ▼
                   collectors/  → items (сырые посты, news.sqlite)
                                  │
                                  ▼
                   dedup        → эмбеддинг + кластеризация → stories (сюжеты)
                                  │
                                  ▼
                   scoring      → LLM: тема, важность 0–10, ИИ/не ИИ, резюме на русском
                                  │
                       ┌──────────┴──────────┐
                       ▼                     ▼
                важность ≥ порога     остальное копится
                → срочно сразу        → дайджест по расписанию
                       │                     │
                       └──────────┬──────────┘
                                  ▼
             бот DEEper и «Радар» → сюжет + кнопки 👍/👎, «Исследовать»
                                  │
                                  ▼
                   feedback     → веса тем и источников
```

### Где что лежит

```
my_browser/news/
├── CLAUDE.md        # что делает часть, как проверить, кто от неё зависит
├── db.py            # схема и подключение (news.sqlite)
├── config.py        # настройки: значения по умолчанию, проверка, сообщения об ошибках
├── sources.py       # таблица источников и стартовый список
├── loop.py          # цикл новостей (поток, раз в минуту)
├── api.py           # API для бота и «Радара»
├── collectors/      # rss.py, hf_papers.py, позже telegram.py
└── …                # dedup, scoring, delivery — на своих этапах
eval/news/           # пары «дубль / не дубль» и замер склейки (этап 4)
```

Бот (`bot/telegram.py`) и «Радар» (`core/ui/radar.py`) обращаются к API news через `common/clients.call("news", ...)`. Цикл стартует в `app.py` вместе с циклом исследований; `NEWS_LOOP=0` его выключает.

## Модель данных (SQLite)

- **sources**: id, kind (`rss` / `hf_papers` / `telegram`), url, name, category (lab / papers / media / analyst / community), lang, owner (организация: ленты одного владельца — один источник), is_primary (официальный первоисточник), ai_filter (общая лента: берём только посты про ИИ), interval (минут между опросами), weight, enabled, last_ok, last_error, fails, etag/modified
- **items**: id, source_id, external_id, url, title, text, links (адреса, на которые ссылается пост), published, seen, lang, backfill (старые посты первого опроса), embedding (blob), story_id
- **stories**: id, first_seen, last_updated, title, topic, importance, is_ai, summary_ru, reason, has_primary, source_count (независимые владельцы), status (`new` / `queued` / `sent` / `dropped`), drop_reason, sent_at
- **feedback**: story_id, value (+1 / −1), created
- **settings**: key, value (время дайджестов, тихие часы, порог срочности, темы, бюджет)
- **state**: что помнит цикл (последний сбор, отметка о работе); **spend**: расход на LLM по дням

Уникальность: `(source_id, external_id)`, чтобы повторный опрос не плодил дубли.

## Настройки (значения по умолчанию)

Часовой пояс Europe/Moscow. Дайджест в 09:00 и 18:00, до 15 сюжетов. Срочное — от важности 8, в тихие часы 23:00–08:00 ждёт утра. Окно склейки 48 часов, порог 0,66 (выбран на eval, этап 4). Темы: модели, исследования, инструменты, безопасность, регулирование, бизнес. Бюджет на LLM — 100 ₽ в месяц, дневной лимит — его пятнадцатая часть (два средних дня).

## Этапы

### Этап 0. Каркас части — сделано 24.10.2026
- Папка `my_browser/news/`, группа зависимостей `news`, `db.py` со схемой, `config.py` с проверкой pydantic, стартовые источники, API, цикл в `app.py`, `CLAUDE.md`.
- **Готово, когда:** часть запускается отдельно и в общем процессе; настройка с ошибкой (неверное время, часовой пояс, число вне диапазона, неизвестная настройка) даёт понятное сообщение по-русски.

### Этап 1. Команда в боте — сделано 24.10.2026
- Бот DEEper уже отвечает только `TELEGRAM_ALLOWED_USERS` (чужим сообщает их ID).
- Команда `/news`: сколько источников и сколько из них работают, посты и сюжеты за сутки, расход на LLM, расписание.
- **Готово, когда:** `/news` показывает статус из API news.

### Этап 2. Сбор из RSS — сделано 24.10.2026
- `collectors/rss.py`: опрос лент по их интервалу, запись в `items` без дублей; общие ленты — только посты про ИИ. Статьи — из API Hugging Face Daily Papers.
- Ошибка одной ленты не роняет цикл: логируется, `last_ok` не обновляется, `fails` растёт.
- **Готово, когда:** разбор сохранённых лент дважды подряд не создаёт дублей; живой сбор по всем источникам кладёт посты в базу.

### Этап 3. Сбор из Telegram — сделано 24.10.2026
- Веб-превью `t.me/s/<канал>`: последние ~20 постов канала, в те же `items`. Каналы подбираем сами и проверяем.
- Медленный и аккуратный опрос, с паузами между каналами.
- **Готово, когда:** посты из 5+ каналов появляются в базе.

### Этап 4. Дедупликация (главная часть) — сделано 25.10.2026
- Эмбеддинг `title + начало текста`, нормализованный.
- Новый item сравнивается со сюжетами за `window_hours`: если близость ≥ порога, добавить в сюжет, иначе создать новый.
- Дополнительный быстрый сигнал: одинаковая ссылка в тексте сразу означает тот же сюжет.
- `has_primary` = в сюжете есть item из источника с `primary` или ссылка на первоисточник. `source_count` = число разных владельцев.
- **Eval:** `eval/news/pairs.jsonl` (103 пары из реальных данных, размечены «дубль / не дубль»), `eval/news/run_dedup.py` считает precision / recall по сетке порогов. Порог выбран по результату и записан в «Решения».
- **Готово, когда:** eval запущен, порог выбран по числам, а не на глаз.

### Этап 5. Оценка и резюме через LLM — сделано 25.10.2026
- Сначала Flash: `is_ai`, `topic`, `importance 0–10`, короткая причина. Ответ строго JSON, с проверкой и повтором при битом ответе.
- Для прошедших фильтр: резюме на русском в 1–2 предложения (для английских источников тоже); главные сюжеты пишет Pro.
- Не-ИИ и низкая важность получают `status=dropped` с `drop_reason`.
- Учёт стоимости каждого вызова; при превышении дневного лимита LLM-вызовы стоп, предупреждение в Telegram.
- Сюжет переоценивается, только если в нём заметно выросло число источников (не на каждый новый пост).
- **Готово, когда:** прогон с тестовой моделью проходит; на реальных данных за сутки расход в пределах лимита.

### Этап 6. Доставка: бот и «Радар» — сделано 25.10.2026
- Формат сюжета:
  ```
  🟢 первоисточник · 7 источников · модели
  <резюме>
  🔗 первоисточник · ещё 6
  ```
  🟢 = есть первоисточник, 🟡 = только пересказы.
- Дайджест в `digest_times`, отсортирован по важности, не больше `digest_max_stories`.
- Срочное (важность ≥ `urgent_min_importance`) сразу, но в тихие часы копится до утра.
- Отправленный сюжет не приходит повторно; если он потом сильно вырос, максимум одно обновление.
- «Радар» в приложении: главный сюжет карточкой, остальные строками, «Копнуть глубже» запускает исследование.
- **Готово, когда:** проверка планировщика с подставленным временем (тихие часы, граница суток, часовой пояс).

### Этап 7. Настройка из Telegram — сделано 25.10.2026
- `/add <ссылка RSS или @канал>`, `/remove`, `/sources` (список и статус)
- `/time 09:00 18:00`, `/quiet 23:00 08:00`, `/urgent 8` (или `off`)
- `/topics`: включить/выключить темы кнопками
- `/pause`, `/resume`
- Изменения пишутся в `settings` и применяются без перезапуска.
- **Готово, когда:** каждая команда проверена, неверный ввод даёт понятную подсказку.

### Этап 8. Обратная связь — сделано 25.10.2026
- Кнопки 👍/👎 под каждым сюжетом, запись в `feedback`.
- Простое обучение: поправки к весам тем и источников, которые влияют на `importance`. Ручные настройки не перезаписываются, поправки хранятся отдельно.
- **Готово, когда:** после серии 👎 по теме её сюжеты опускаются в дайджесте.

### Этап 9. Отчёт об отсеянном — сделано 25.10.2026
- `/dropped`: что отфильтровано за сутки, с причиной, сгруппировано.
- Кнопка «Это было важно»: сюжет отправляется, и это считается 👍 (учится на пропусках).
- **Готово, когда:** можно найти и вернуть ошибочно отсеянный сюжет.

### Этап 10. Работа на Railway — сделано 25.10.2026
- Часть уже работает в общем процессе на Railway; `news.sqlite` лежит на volume.
- Ежедневная копия базы.
- **Готово, когда:** работает сутки без вмешательства; `/news` показывает живые источники.

## Решения

**24.10.2026, встраивание в DEEper** (ответы владельца):
- Новости — пятая часть DEEper, а не отдельный проект `ai-news-radar/`: своя папка, `CLAUDE.md`, группа зависимостей и база `news.sqlite` на volume. Работает в общем процессе на Railway, а не на VPS с Docker Compose.
- Доставка — в бот DEEper и в «Радар» приложения. Отдельный бот не нужен. Чужим бот, как и раньше, сообщает их Telegram ID, а не молчит.
- Telegram-каналы читаем через веб-превью `t.me/s`, а не через Telethon: без входа в аккаунт и без риска для него. Закрытые каналы так не прочитать.
- Бюджет — до 100 ₽ в месяц. Дневной лимит — 1/15 (два средних дня, 6,67 ₽): после деплоя весь накопленный объём стоит около 3 ₽, и при лимите 1/30 на новые сюжеты того же дня денег бы не осталось. Месячные 100 ₽ — настоящий предел. Flash оценивает, Pro пишет резюме главных сюжетов. В первой версии плана было $0,5 в день: это ≈ 1 350 ₽ в месяц, больше всего бюджета DEEper.
- Без pytest, как во всём DEEper: проверка одноразовыми прогонами и `/check-project`. Eval склейки на этапе 4 остаётся: это замер.
- Простой цикл в потоке вместо APScheduler; настройки в SQLite с проверкой pydantic вместо `config.yaml`.

**25.10.2026, склейка (этап 4).**
- Модель — paraphrase-multilingual-MiniLM-L12-v2 через fastembed (220 МБ), в дочернем процессе: память нужна только на время пачки. 300 постов — около 8 секунд.

**25.10.2026, настройка из Telegram (этап 7).**
- `/remove` не удаляет источник, а выключает: его посты остаются в сюжетах, а стартовый источник не вернётся сам; включить снова — `/add` с тем же адресом.
- `/add` сначала проверяет источник: у ленты должны быть посты, у канала — открытое превью с постами. Добавленный источник считается СМИ и опрашивается раз в 15 минут.
- `/pause` останавливает оценку и сообщения, а сбор и склейка идут, чтобы после паузы ничего не потерялось.
- Темы фильтруют дайджесты, срочное и «Радар»; оцениваются все сюжеты, чтобы включённая обратно тема сразу была с оценками.
- Проверено через диспетчер бота: каждая команда с верным и неверным вводом; неверное время, порог 11, «abc», адрес без ленты и закрытый канал получают понятный ответ.

# DEEper — глубокие исследования с длинными отчётами

Личный исследовательский поисковик: по теме он сам планирует запросы, ищет и читает десятки источников и пишет структурированный отчёт на русском — с оглавлением, разделами, заключением и списком источников. Отчёт сохраняется в PDF, DOCX и Markdown. Работает в веб-приложении, через Telegram-бота и из командной строки.

Оформление — по брендбуку AVEN (made by aven): тёмная тема «ночь / бумага / бордо / янтарь», шрифты Unbounded, Onest и JetBrains Mono.

Внутри: [GPT Researcher](https://github.com/assafelovic/gpt-researcher) (оркестрация исследования), [SearXNG](https://github.com/searxng/searxng) (бесплатный веб-поиск) или Tavily, научные базы arXiv и OpenAlex, модель DeepSeek.

> Старая версия DEEper (Groq + Tavily) сохранена в ветке [`legacy`](https://github.com/MrBoomer1981/DEEper/tree/legacy).

## Режимы

| Режим | Что делает | Пример |
|---|---|---|
| `detailed` | введение, отдельное исследование под каждую подтему (все сразу), заключение | ~5–7 мин на Pro, ~5 на Flash; до 5 000 слов (обычно 3,5–4,5 тыс.), 35–40 источников в тексте |
| `deep` | рекурсивный поиск вширь и вглубь, затем один отчёт | дольше всех |
| `quick` | один проход | ~1–2 мин, 2–3,5 тыс. слов |

Источники: `web` (SearXNG или Tavily), `academic` (arXiv, OpenAlex), `all` — по умолчанию.

Любой отчёт не длиннее 5 000 слов: подробный делит их между введением, разделами и заключением. Итоговый текст и ответы на вопросы пишет DeepSeek V4 Pro (`--writer pro`, по умолчанию), поиск, планирование и отбор источников — DeepSeek Flash. Для дешёвых черновиков: `--writer flash` или переключатель «Pro / Flash» в приложении. Стоимость каждого отчёта и вопроса считается по реальным токенам и тарифам DeepSeek (с учётом ночной скидки) и показывается в рублях. На тестовой теме быстрый отчёт: Flash — 0,87 ₽, Pro — 2,30 ₽.

Поиск с упором на англоязычные источники: модель формулирует поисковые запросы на английском (для тем про конкретную страну — один на её языке), исходный запрос ищется как есть, а отчёт пишется на русском. На тестовой теме доля англоязычных источников выросла с 26% до 82%.

Отбор источников: до скачивания страниц модель видит заголовок и описание каждого найденного результата и ставит оценку 0–3 за релевантность теме, надёжность и свежесть. Известные домены (`.gov`, `.edu`, научные издательства, IEA, ООН, крупные СМИ) только повышают оценку релевантного источника. Не по теме, магазины, соцсети и мусор отбрасываются, SEO-блоги берутся, только если ничего лучше нет. С одного сайта — не больше 2 ссылок на запрос и 5 на исследование. На тестовой теме: статей не по теме было 18 из 32, стало 0; доменов 11 → 16; доля источников, использованных в тексте, 12% → 36%. Отключить: `SOURCE_FILTER=off`.

## Запуск на своём компьютере

Нужны Docker, [uv](https://docs.astral.sh/uv/) и ключ [DeepSeek](https://platform.deepseek.com/api_keys). На macOS для PDF: `brew install pango`.

```bash
cp .env.example .env          # впишите DEEPSEEK_API_KEY и SEARXNG_SECRET (openssl rand -hex 32)
docker compose up -d          # локальный SearXNG на 127.0.0.1:8080
uv run research.py "тема"     # отчёт появится в reports/
uv run research.py "тема" --mode deep --sources all --words 2500
uv run app.py                 # приложение, исследователь и бот (если задан токен) в одном процессе
```

## Из чего состоит

Четыре части, каждую можно улучшать и перезапускать отдельно:

| Часть | Что делает |
|---|---|
| **core** — ядро | веб-приложение, API, библиотека отчётов, очередь исследований, список заблокированных сайтов |
| **worker** — исследователь | само исследование (GPT Researcher и наши доработки), подсказки, ответы на вопросы, сборка PDF и DOCX |
| **search** — поиск | отбор источников и чтение страниц с запасными способами (Europe PMC, OpenAlex, Jina Reader) |
| **bot** | Telegram-бот, работает через API ядра |

`uv run app.py` запускает всё в одном процессе — так работает и Railway. По отдельности: `uv run python -m my_browser.core` (и `.worker`, `.search`, `.bot`) с адресами друг друга в `CORE_URL`, `WORKER_URL`, `SEARCH_URL` и общим `SERVICE_TOKEN`. Очередь исследований хранится в базе: если сервер перезапустится посреди исследования, оно станет «прервано» и его можно перезапустить кнопкой в приложении или в боте.

### Работа над одной частью

У папки каждой части (`my_browser/core`, `worker`, `search`, `bot`, а ещё `common`, `eval` и `proxy`) свой `CLAUDE.md`. В нём написано, что делает часть, как запустить и проверить её отдельно и чего от неё ждут остальные. Отдельную сессию Claude Code можно открыть прямо в папке:

```bash
cd my_browser/search && claude
```

Такая сессия сама подхватывает общие правила проекта и память и видит весь репозиторий. Коммитит она только свои файлы. Перед коммитом сессия запускает `/check-project`, бесплатную проверку всего проекта: все модули импортируются, а одно исследование проходит целиком с тестовой моделью `dev/mock_llm.py` вместо DeepSeek. Несколько сессий могут работать одновременно: у каждой свои порты и своя папка для отчётов.

## Приложение (телефон, Mac, браузер)

Сделано прежде всего для телефона. Внизу четыре раздела: «Поиск», «Радар», «Библиотека», «Фокус». Они переключаются мгновенно, без перезагрузки страницы, а отчёт и ход исследования открываются с плавным переходом. Оформление и маскот Дип-Диггер описаны в `DESIGN_HANDOFF.md`.

- **Поиск.** Тема вводится в поле внизу экрана. «Подробно» открывает настройки: режим, источники, модель, проверку фактов и «Уточнить тему». Уточнение задаёт 2–3 вопроса с вариантами (регион, цель, аспект), и ответы встраиваются в тему.
- **Ход исследования.** Процент, этап и последние прочитанные источники. Экран можно закрыть: отчёт появится в «Библиотеке».
- **Отчёт.** На экране только текст. Ссылки заменены номерами, оглавление «3 / 9 ▾» следит за прокруткой. В «⋯» лежат PDF, DOCX и MD, источники с блокировкой сайтов и вопросы по отчёту. Там же «Сократить до 1 500 слов»: Pro оставляет выводы, ключевые факты и числа с их ссылками, а краткая версия сохраняется рядом с полной. На отчёте в 7 500 слов это заняло 28 с и стоило 2,15 ₽. Выделенный текст можно сохранить в закладки, задать по нему вопрос или начать по нему новое исследование («Глубже»).
- **«Что исследовать дальше»** в конце отчёта: 5 следующих тем (углубить, рядом, проверить). Новый отчёт становится продолжением текущего; рядом показаны продолжения и похожие отчёты из библиотеки. Тот же раздел есть в конце PDF, DOCX и Markdown. Если ответа на вопрос в отчёте нет, приложение предложит тему для отдельного исследования.
- **«Проверка фактов»**: после написания отчёта каждое утверждение со ссылкой сверяется с той страницей, которую читало исследование. Если сказанное есть в другом прочитанном источнике, ссылка меняется на него; если источник даёт другие числа, даты или имена, предложение исправляется по нему. Неподтверждённые места отмечены «?» в тексте и собраны в разделе «Проверка фактов» в конце отчёта (и в PDF, DOCX, Markdown). По умолчанию проверка включена для подробного и глубокого режимов. Переключатель есть в «Подробно» на экране поиска и в «Фокусе».
- **Библиотека**: отчёты (идущие исследования сверху), закладки и поиск по всем отчётам.
- **Фокус**: настройки по умолчанию и пресеты («Учёный», «Аналитик», «Новости»), сайты, которые не брать, граффити.
- **Радар**: пока здесь темы «Что исследовать дальше» из последних отчётов, которые ещё не исследованы. Новости и слежка за темами появятся позже.

```bash
uv run app.py                 # http://127.0.0.1:8501 (порт 8080 занят локальным SearXNG)
```

На Railway приложение работает в том же сервисе, что и бот (общая история отчётов), и закрыто паролем `APP_PASSWORD`.

**Установить без App Store.** На iPhone: Safari → «Поделиться» → «На экран Домой». На Mac: Safari → «Файл» → «Добавить в Dock». Появится отдельное приложение DEEper со своей иконкой (на Mac — в Dock, Launchpad, Spotlight и Cmd+Tab).

## Telegram-бот

Пришлите тему — бот предложит кнопками режим, источники, проверку фактов (и «Уточнить тему»), покажет ход работы и пришлёт PDF, DOCX, Markdown, заключение и темы «что исследовать дальше»: номер темы запускает её как продолжение отчёта. Ответьте на сообщение с номером отчёта (`#N`), чтобы задать вопрос по нему; если ответа в отчёте нет, бот предложит исследовать вопрос отдельно.

| Команда | |
|---|---|
| `/history` | последние отчёты |
| `/view N` | прислать отчёт N ещё раз |
| `/search текст` | поиск по всем отчётам |
| `/ask N вопрос` | вопрос по отчёту N |
| `/delete N` | удалить отчёт N |
| `/block домен` | не использовать сайт как источник (`/unblock`, `/blocked`) |

Бот личный: отвечает только пользователям из `TELEGRAM_ALLOWED_USERS`. Остальным он сообщает их Telegram ID — так удобно узнать свой.

## Деплой на Railway

Сборка по `Dockerfile`: в настройках сервиса на Railway выбран сборщик Dockerfile (Settings → Build → Builder), одна реплика. SearXNG на Railway не поднимается, поэтому веб-поиск там идёт через Tavily (бесплатно 1000 запросов в месяц): он включается сам, когда задан `TAVILY_API_KEY`, а `SEARX_URL` — нет. Явно выбрать поиск можно переменной `WEB_RETRIEVER`.

**Из России без VPN.** Адрес Railway (`*.up.railway.app`) из российских сетей не открывается, а Cloudflare открывается. Поэтому перед приложением стоит бесплатный прокси на Cloudflare Workers (`proxy/`): телефон открывает `deeper.<поддомен>.workers.dev`, а прокси передаёт всё приложению на Railway. Выложить его: в папке `proxy/` выполнить `npx wrangler login`, `npx wrangler secret put ORIGIN` (адрес приложения на Railway) и `npx wrangler deploy`. На мобильном интернете прокси не открывается: с июня 2025 года российские провайдеры пропускают к адресам Cloudflare только первые ~16 КБ на соединение. Для этого подготовлен свой сервер в России (`proxy/ru/`), пока он в архиве (`plan.md`, раздел «Архив»).

Переменные сервиса:

| Переменная | Значение |
|---|---|
| `DEEPSEEK_API_KEY` | ключ DeepSeek |
| `TELEGRAM_BOT_TOKEN` | токен от @BotFather (старое имя `TELEGRAM_TOKEN` тоже подходит) |
| `TELEGRAM_ALLOWED_USERS` | ваш Telegram ID (несколько — через запятую) |
| `APP_PASSWORD` | пароль входа в веб-приложение |
| `TAVILY_API_KEY` | ключ [Tavily](https://app.tavily.com) |
| `JINA_API_KEY` | необязательно: бесплатный ключ [Jina Reader](https://jina.ai/reader). Страницы, которые не скачались напрямую, читаются через Jina: с ключом 500 в минуту, без ключа 20 |

Чтобы отчёты и история переживали передеплой, подключите к сервису Volume с путём монтирования `/app/reports`.

## Настройки

Модели, длина отчётов, число подтем и параметры глубокого режима — в `config.json`. Любой ключ оттуда можно переопределить переменной окружения или строкой в `.env`.

## Замеры качества

```bash
uv run eval/run.py                    # 7 постоянных тем из eval/topics.txt, ≈ 10 ₽ за прогон
uv run eval/run.py --topics 1,4 --label проба
uv run eval/run.py --factcheck        # с проверкой фактов: точность цитат до и после исправлений
uv run eval/run.py --rejudge 2026-10-18_2327_3.1-reader   # заново оценить отчёты прошлого замера
```

Каждая тема проходит обычное исследование (быстрый отчёт, текст пишет Flash), отчёты складываются в `eval/reports`, а не в библиотеку. Таблица с источниками, долей англоязычных и авторитетных сайтов, нескачанными страницами, стоимостью и точностью цитирования появляется в `eval/results/` рядом со средними прошлого замера. Так видно, улучшило ли поиск очередное изменение.

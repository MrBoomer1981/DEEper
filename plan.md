# DEEper — план улучшений

Версия от 18 октября 2026. Сделанное отмечаем галочкой `[x]`. Цифры «сейчас» взяты из реальных прогонов в `reports/`. Лимиты и цены сервисов проверены в октябре 2026, ссылки в конце.

**Правила**
- Любое изменение поиска проверяем замером «до/после» на постоянном наборе тем (этап 2), а не на одном отчёте.
- На модели и сервисы тратим до 300 ₽ в месяц. Новые сервисы подключаем, только если у них есть бесплатный лимит без карты.
- Главное — длинные отчёты. Точность и проверяемость текста важнее скорости.

### Слабые места
1. **В текст попадает треть собранного.** Ссылки есть только на 36% источников. Остальные отнимают время на скачивание и токены в контексте.
2. **Цифры никто не проверяет.** Модель может исказить число или приписать его не тому источнику. В быстром и глубоком режимах стиль ссылок меняется от запуска к запуску: то ссылки прямо в тексте, то APA со списком в конце. Такой отчёт трудно проверить.
3. **По одному веб-поисковику.** Через локальный SearXNG отвечают только Google CSE и Yahoo. На Railway работает один Tavily с 1 000 запросов в месяц на всё.
4. **Из arXiv берётся только аннотация.** Скрейпер GPT Researcher не читает саму статью. OpenAlex уже берёт открытый PDF, когда он есть.
5. **Неизвестно, сколько страниц не скачалось.** BeautifulSoup не видит текст на JS-сайтах, а долю пустых страниц мы не измеряли.
6. **Замеры ручные, тестов нет.** Каждое улучшение проверено на одной теме одним прогоном. Однажды тест случайно потратил 2,43 ₽ на настоящий Pro.
7. **Передеплой Railway обрывает идущее исследование**, потому что очередь живёт только в памяти.

## Этап 1. «Что исследовать дальше» — сделано 18.10.2026

Как подсказки «Related» в Perplexity, только для длинных исследований. После отчёта DEEper предлагает следующие темы, и любую можно запустить в два клика.

- [x] **Предложения.** После сохранения отчёта один вызов Flash читает оглавление, выводы и пробелы и предлагает 5 тем трёх видов:
  - *углубить*: подтема, которую отчёт затронул вскользь;
  - *рядом*: смежная область;
  - *проверить*: где источники расходятся, риски, контраргументы, открытые вопросы.

  У каждой темы есть готовая формулировка запроса, строка «зачем» и рекомендуемый режим. Темы хранятся в JSON отчёта (`followups`), поэтому повторное открытие ничего не стоит. Для старых отчётов есть кнопка «Предложить темы».
- [x] **Приложение.** Под отчётом блок «Что исследовать дальше». Клик открывает форму нового исследования с заполненными темой, режимом и источниками. Запуск — второй кнопкой, чтобы случайный клик не тратил деньги.
- [x] **Уже в библиотеке.** Рядом показываем до 3 похожих прошлых отчётов (поиск FTS5, бесплатно), чтобы не исследовать заново то, что уже есть.
- [x] **Ветки исследований.** Новый отчёт хранит `parent`. На странице видно, продолжением какого отчёта он стал и какие отчёты продолжают его самого. Получается дерево исследований по теме.
- [x] **Бот.** Под итоговым сообщением кнопки с темами, затем выбор режима и запуск. Сами темы хранятся на сервере, а в кнопке только номер: Telegram ограничивает данные кнопки 64 байтами.
- [x] **Из вопросов.** Если ответ на вопрос по отчёту — «в отчёте этого нет», под ним появляется кнопка «Исследовать этот вопрос». `ask.py` уже просит модель подсказать, что исследовать отдельно.
- [x] **В файлах.** Раздел «Что исследовать дальше» в конце md, pdf и docx.
- [x] **Уточнение перед стартом** — кнопкой «Уточнить», как в deep research у ChatGPT: 2–3 вопроса с готовыми вариантами ответа (период, регион, для чего нужен отчёт), ответы встраиваются в тему. Цена ≈ 0,01–0,05 ₽.

Цена по замеру: 0,05 ₽ на подбор тем. Быстрый отчёт на Flash вместе с темами — 0,85 ₽.

## Этап 2. Замеры и тесты

Без повторяемого замера улучшение не отличить от случайности: до сих пор каждое изменение поиска проверялось одним прогоном на одной теме.

- [ ] `eval/topics.txt`: 8 постоянных тем разного типа:
  - наука и техника;
  - рынок и бизнес;
  - медицина;
  - право РФ;
  - свежие новости;
  - история;
  - программирование;
  - спорный вопрос, где источники расходятся.
- [ ] `eval/run.py` гоняет по каждой теме быстрый отчёт на Flash и пишет таблицу в `eval/results/<дата>.md`. Что считает:
  - источники, разные домены, долю англоязычных и авторитетных;
  - долю источников, на которые есть ссылка в тексте;
  - долю пустых и нескачанных страниц;
  - долю источников не по теме (Flash судит по заголовку);
  - **точность цитирования**: берём 30 случайных пар «утверждение → ссылка», и Flash проверяет, подтверждает ли страница утверждение. Это метод FACT из DeepResearch Bench;
  - слова, время, стоимость, обрезанные ответы.
- [ ] Прогнать один подробный отчёт на Pro: его цена пока только оценка (7–9 ₽).
- [ ] Тесты без затрат:
  - pytest для `rank`, `readable_url`, `is_peak` и поиска по библиотеке;
  - сквозной тест на поддельной модели, с поддельным сервером в `tests/`. Писатель в тесте тоже должен быть поддельным, иначе переключатель подставит настоящий Pro.
- [ ] GitHub Actions запускает тесты на каждый пуш (для публичного репозитория бесплатно).

Цена: ≈ 10 ₽ за прогон набора. Гоняем только когда меняем поиск.

## Этап 3. Поиск v3

### Обязательная часть

**3.1. Ссылки прямо в тексте, всегда**
- [ ] Промпт быстрого и глубокого режимов требует markdown-ссылку после каждого факта и числа. Список «Источники» собирается только из процитированных ссылок, как уже сделано в подробном режиме.
- 0 ₽. Без этого не получится проверка фактов. Метрика: доля чисел со ссылкой.

**3.2. Проверка фактов**
- [ ] Из готового текста извлекаются утверждения с числами, датами и именами вместе с их ссылками.
- [ ] Каждое утверждение сверяется с фрагментами той же страницы, которые видел писатель. Контекст исследования уже в памяти, так что повторно ничего скачивать не нужно. Flash ставит оценку: подтверждено, частично, нет в источнике или противоречит.
- [ ] В конце отчёта раздел «Проверка фактов»: сколько утверждений проверено и подтверждено, плюс список сомнительных. В приложении сомнительные места помечены.
- [ ] Опция «Исправить»: Pro переписывает только помеченные предложения.
- Цена (оценка): +0,5–1 ₽ к быстрому отчёту и +2–3 ₽ к подробному. Проверка включается переключателем в приложении и боте, для подробного она включена по умолчанию. Метрика: точность цитирования из этапа 2 до и после.

**3.3. Второй поисковик — Exa**
- [ ] Exa ищет по смыслу, а не по словам. Он силён в аналитике, исследованиях и длинных статьях, поэтому хорошо дополняет поиск в духе Google. Бесплатно даёт $10 каждый месяц без карты, это примерно 1 400–2 500 запросов в зависимости от типа поиска.
- [ ] Веб-поиск: SearXNG + Exa локально, Tavily + Exa на Railway. Наш отбор источников уже работает с любым числом поисковиков.
- [ ] Ретривер `exa` в GPT Researcher не отдаёт заголовки, а наш отбор опирается на них. Нужен свой небольшой адаптер и пакет `exa-py`.
- 0 ₽. Метрики: число разных доменов, доля авторитетных, точность цитирования.
- Почему не другие:
  - Brave в феврале 2026 убрал бесплатный тариф: теперь $5 кредита в месяц, и то только с картой и публичной атрибуцией;
  - Tavily уже подключён, и его 1 000 запросов в месяц делят все запуски.

**3.4. Полные тексты научных статей**
- [ ] arXiv: брать HTML-версию статьи (`arxiv.org/html/…`), а если её нет, то PDF. Оставлять аннотацию, введение, результаты и выводы с лимитом по длине, чтобы не раздувать контекст.
- [ ] OpenAlex: добавить бесплатный `OPENALEX_API_KEY`. Без ключа OpenAlex разрешает только эпизодическое использование («casual use»). Ключ даёт $1 бесплатного лимита в день и 30 запросов в секунду вместо 10. Ретривер ключ уже поддерживает.
- 0 ₽. Метрика: доля научных источников с полным текстом и доля процитированных среди них.

**3.5. Больше источников в тексте**
- [ ] На наборе тем сравнить два варианта: промпт «используй и цитируй все релевантные источники» и сбор поменьше (`MAX_SOURCES_PER_QUERY` 5 вместо 8). Оставить вариант с лучшим сочетанием доли процитированных, точности и цены.
- 0 ₽ или дешевле, чем сейчас.

**3.6. Учёт лимитов поисковиков**
- [ ] Считать запросы к Tavily и Exa по отчётам и за месяц, показывать в приложении и предупреждать при 80% лимита. Сейчас о кончившемся лимите мы узнаем только по сломанному исследованию.

### По результатам замеров

Это делаем, только если этап 2 покажет проблему.

- [ ] **3.7. Добор пробелов.** Как рефлексия в open_deep_research: после первого прохода по подтеме Flash сверяет собранное с планом, находит вопросы без данных и делает 2–3 точечных запроса. Цена: +1 вызов Flash и несколько запросов на подтему, +10–20% времени.
- [ ] **3.8. Запасной парсер.** Нужен, если пустых страниц больше 10%. Страницы, где BeautifulSoup вернул меньше 500 символов, читаем повторно через Jina Reader. Он бесплатный: без ключа 20 запросов в минуту, с бесплатным ключом 500. На Railway альтернатива — Tavily Extract, 1 кредит за 5 страниц.
- [ ] **3.9. Язык поиска по теме.** Сейчас ищем английскими запросами плюс исходным запросом как есть. Для тем про конкретную страну добавляется один запрос на её языке. Если темы про право и рынок РФ проседают, пусть планировщик сам выбирает долю русских запросов, а оценка источников не занижает официальные русские сайты.
- [ ] **3.10. Перепечатки.** Удалять почти одинаковые тексты с разных сайтов (например, пресс-релизы) и оставлять самый надёжный. Это экономит контекст.
- [ ] **3.11. Поиск фрагментов по смыслу.** Небольшая локальная мультиязычная модель эмбеддингов (0,2–0,5 ГБ памяти) сопоставляет английский запрос и русскую страницу лучше, чем BM25. Это 0 ₽, но нужно больше памяти и времени на Railway, поэтому пробуем последним.

## Этап 4. Свои документы и наблюдение за темами

- [ ] **Свои файлы.** PDF и DOCX можно загрузить в приложение или отправить боту. С ними можно:
  - задавать вопросы по документу, как сейчас по отчёту;
  - делать исследование «документ + веб»: GPT Researcher умеет смешивать свои файлы с поиском (`report_source="hybrid"`).

  Файлы лежат на volume в `reports/docs/`. 100 страниц — около 60 тыс. токенов: ≈ 1 ₽ за проход на Flash и ≈ 3 ₽ на Pro.
- [ ] **Наблюдение за темой.** Кнопка «Следить»: раз в неделю или месяц быстрое исследование повторяется, и приходит отчёт «Что нового»: новые источники и изменившиеся цифры по сравнению с прошлым разом. Проверка идёт ночью по Москве, вне пика это вдвое дешевле. Результат приходит в бот. Одна проверка стоит ≈ 1–2,5 ₽, 4 темы раз в неделю — ≈ 20–40 ₽ в месяц.
- [ ] **Запуск вне пика.** Если исследование запускают в пиковые часы (будни 04:00–07:00 и 09:00–13:00 по Москве), предлагать отложить его до конца пика: так вдвое дешевле.

## Этап 5. Надёжность и обслуживание

- [ ] **Очередь переживает перезапуск.** Задания хранятся в SQLite. После передеплоя прерванные задания видны в приложении и боте и перезапускаются одной кнопкой.
- [ ] **Кэш DeepSeek.** DeepSeek сам кэширует одинаковое начало запроса, и такой вход для Pro стоит $0,044 вместо $1,32 за 1M токенов. Значит, второй вопрос к тому же отчёту должен стоить в разы дешевле; проверить это по полю `cached` в стоимости. В подробном режиме ставить общий контекст в начало промптов разделов.
- [ ] **Хвосты.** Удалить старый репозиторий `my-browser`: для этого нужно выполнить `gh auth refresh -h github.com -s delete_repo`. Исправить email в глобальном git-конфиге: в нём нет «@».

## Что ещё изучить: идеи из других проектов

- **[DeepResearch Bench](https://github.com/Ayanami0730/deep_research_bench)** (ICLR 2026): 100 задач уровня PhD из 22 областей и две методики оценки.
  - RACE оценивает полноту, глубину, следование заданию и читаемость. Возьмём её, чтобы сравнивать Flash и Pro не на глаз.
  - FACT проверяет ссылки: извлекает пары «утверждение → URL» и смотрит, подтверждает ли страница утверждение. Возьмём её для метрики точности цитирования (этап 2).
- **[STORM](https://github.com/stanford-oval/storm)** (Стэнфорд): план статьи строится из смоделированных разговоров автора, у которого есть определённая точка зрения, с экспертом, который опирается на источники. Для подробного режима: генерировать подтемы от лица 3–4 ролей (инженер, экономист, регулятор, скептик). Охват будет полнее, а стоит это один вызов Flash.
- **[open_deep_research](https://github.com/langchain-ai/open_deep_research)** (LangChain): руководитель раздаёт подзадачи параллельным исследователям, и каждый сжимает свои находки до написания. Отсюда добор пробелов (3.7) и сжатые конспекты по подтемам, чтобы писатель читал меньше токенов.
- **[node-DeepResearch](https://github.com/jina-ai/node-DeepResearch)** (Jina): цикл «поиск → чтение → рассуждение» идёт, пока не найден ответ или не кончился бюджет токенов. Идея для нас — бюджет в рублях: «исследуй на 5 ₽» вместо фиксированной глубины.
- **[Local Deep Research](https://github.com/LearningCircuit/local-deep-research)**: полностью локальный режим и разные стратегии поиска. Запасной вариант за 0 ₽ и материал для сравнения стратегий.
